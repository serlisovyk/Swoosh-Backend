# Plan: Dockerfile + docker-compose for the app

Issue: MY-70 · No spec — infra/tooling, no public/data contract change.

## Context

No way to build/run the backend in a container. `bun.lock` is the real lockfile (MY-72); `MONGO_URI` already points at Atlas (MY-45); `GET /api/v1` and `GET /api/v1/health` exist for a smoke check (MY-48, merged). Reference shape: `teacoder-team/backend`'s `Dockerfile` (multi-stage, non-root), adapted to this repo's bun/Nest setup — no Prisma/yarn specifics.

## Commit breakdown

1. **docs(ai): plan for Docker packaging** — this commit, plan only, no code.
2. **feat: add Dockerfile, docker-compose.yml, .dockerignore**
   - `Dockerfile`, two stages:
     - `builder` (`oven/bun:1-alpine`): copy `package.json`/`bun.lock`, `bun install --frozen-lockfile`, copy source, `bun run build`, then drop dev deps (`rm -rf node_modules && bun install --frozen-lockfile --production`) to get a prod-only `node_modules`.
     - `runner` (`node:24-alpine` — plain Node, matching `.nvmrc`, not a bun runtime image): copy `package.json`, prod `node_modules`, `dist` from the builder stage; `USER node`; `CMD ["node", "dist/main.js"]`.
   - `.dockerignore`: `node_modules`, `dist`, `.env`, `.git`, `ai/`, `*.md` — `.env` never enters the build context.
   - `docker-compose.yml`:
     - `app` service: `build: .`, `env_file: .env`, `ports: ["3001:3001"]` (matches the current `.env` `PORT`).
     - optional `mongo` service behind `profiles: ["local-db"]` — not started by a plain `docker compose up`, and not wired into `app`'s `MONGO_URI` (that still points at Atlas either way); it's a convenience for local Mongo when someone wants one, nothing more.
3. **docs: document Docker usage in README, add root files to map**
   - `README.md`: short "Docker" section — build/run commands, note that `app` alone is the default and `mongo` needs `--profile local-db`.
   - `ai/map.md`: note the three new root files (`Dockerfile`, `docker-compose.yml`, `.dockerignore`) and what each does.

## Verification

- `docker build -t swoosh-server .` — succeeds.
- `docker compose up` — `app` starts, `GET /api/v1` and `GET /api/v1/health` respond through the published port.
- Image runs as `node`, not root (`docker run --rm swoosh-server whoami` or equivalent).
- `bun run lint` / `bun run build` outside the container — unaffected, still green.
